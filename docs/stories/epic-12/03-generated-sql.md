# Story 3: Generated-SQL panel

**Epic:** 12 — Forge: SCHEMA & ENTS modes  
**Status:** 🔲 Not started  
**Priority:** High — it is what makes the schema editor trustworthy

**Depends on:** Story 2

## Context

The right-hand panel shows the `CREATE TABLE comp_*` the interpreter will run. Its value is entirely in being the *real* thing: a preview generated by a second implementation would drift, and a preview that drifts is worse than none, because it is believed.

So it calls `storage.MigrateComponent` — the exported entry point to the generator the engine itself uses. That is a one-line wrapper over `componentTableSQL`, which means the preview and the migration cannot disagree by construction.

**There is a bug to fix first.** `componentTableSQL` iterates `comp.Properties` with `for propName, prop := range` — a Go map, so column order changes between calls. In the engine that is invisible: the DDL runs once at startup and nobody reads it. In a live preview it is glaring — the columns visibly reshuffle as you type. The rebuild path in `ddlgen.go` already sorts, so the two halves of the generator disagree with each other today regardless of Forge.

The plan proposed sorting to match. Since Epic 11 Story 2, there is a better answer: `Component.PropertyOrder` records the order the author wrote. Emitting columns in that order is deterministic *and* makes the DDL read like the file it came from.

## Acceptance Criteria

- [ ] The panel renders the output of `storage.MigrateComponent` — no second generator, and a test that asserts the panel's text equals that function's output for every fixture
- [ ] `componentTableSQL` emits columns in authored property order, falling back to sorted when no order was recorded
- [ ] Repeated calls produce identical SQL — asserted by generating twice and comparing, not by inspection
- [ ] `ddlgen.go`'s rebuild path uses the same ordering rule, so the two halves of the generator agree
- [ ] The preview updates as the component is edited, over the page's SSE stream, without a reload
- [ ] Every shape renders correctly: object (one column per property), `entity-ref` (`target_entity_id`), the four scalars (`value`), and array
- [ ] **Arrays are shown honestly** as the single JSON `TEXT` column they are, with a note saying so — the design's junction-table shape does not exist and must not be implied
- [ ] The panel is `--inset` with mono text, per the design
- [ ] `go test ./...` passes

## Notes

- **The determinism fix is engine code, and it changes generated DDL.** It affects the order columns are created in for a fresh database. Column order is not semantically meaningful in SQLite for named access, but it is visible in `PRAGMA table_info` and in `introspect.go`'s output, so check the introspection tests before assuming it is free.
- Do not add a `NOT NULL` toggle to the preview by hand. The generator decides; the panel reports.
- The DDL is engine-owned text, so it is mono and it is not case-mangled — the same rule the engine-status readout's source suffix follows.
- If `MigrateComponent` returns an error for a shape, show the error. An editor that silently shows nothing for an invalid component teaches you that nothing is wrong.
